# AgentDesk

Chinese-speaking insurance agents serve clients in Chinese, but their product
documents are in English. Every client question becomes a search through dozens
of PDF pages, and every answer carries the risk of saying something the
documents do not support.

AgentDesk closes that gap: **ask in Chinese, get an answer grounded in the
English source, with the page number and the verbatim quote attached** — and
when the documents do not contain the answer, it says so instead of inventing
one.

## Citations the model cannot fake

Every factual claim carries a citation card with the document, the page, and
the exact English sentence — and a link that opens the PDF at that page. The
model never produces any of that metadata. It emits a draft under a strict zod
schema; code then verifies that every quote is an exact substring of the
retrieved chunk, injects document and page metadata from retrieval, and drops
any claim that fails validation before render, with an integrity assertion.
Bounded repair: one retry, then an honest `MODEL_OUTPUT_INVALID` refusal.

Asked for a number the documents don't contain, it refuses —
`资料不足 · INSUFFICIENT_EVIDENCE` — still cites what the documents _do_ say,
and lists exactly what is missing. Asked which product is "best", a
deterministic rule stops the request before the model is ever called.

## A comparison table with no model in it

The 13-row product comparison is **generated by code, not by a model** — the
model doesn't choose facts, assign them to products, compare numbers, or build
citations. Four availability states never collapse into each other: a
documented "this product does not offer riders" is a _cited fact_, not a blank;
a structured value that disagrees with its document renders nothing and reports
`conflict` — fail closed. There is no score, no winner, no "better fit" field
anywhere in the data structure.

## Review as four questions, not one badge

A draft sent for review is frozen: a snapshot hashed with SHA-256, immutable at
the database level, with append-only audit triggers that refuse UPDATE
entirely. The reviewer sees four axes kept deliberately apart — are the facts
trustworthy (code), how far may this travel (code), how much authority does it
need (code), and how far has the work actually got (a human). A 67-year-old
client replacing an annuity produces `complete` + `block_client_draft` +
`licensed_agent_required` + `pending_review`: the facts check out, it must not
go to a client, a licensed agent has to look, and nobody has yet.

Post-review automation can produce exactly **one kind of artifact: an internal
task**. The task-type enum has no client-facing member and the payload has no
recipient field — "this can never be emailed to a client by mistake" is not a
rule someone has to remember, it is a value the system cannot express.

## Architecture

```text
English product PDFs (generated from one source of truth)
   │  heading/table-aware chunking, page metadata
   ▼
Supabase Postgres + pgvector
   │
   ├─► Q&A:        zh query ─► multi-route retrieval ─► strict-schema draft
   │                         ─► code verifies every quote ─► grounded answer
   ├─► Compare:    fact registry ─► 13-row table (no model)
   ├─► Review:     frozen snapshot + sha256 ─► human decision ─► audit log
   └─► Automation: terminal review ─► internal task ─► n8n webhook / mock
```

Retrieval is measured, not assumed: three language-dependent routes (original,
deterministic glossary, LLM rewrite), kept or cut per language based on
observed hit@1 — the rewrite materially improved Chinese recall every run, and
added rank noise on mixed-language queries, so it only runs where it earns its
place.

## Checked, not vibes

Not by asking a model whether it did well. Deterministic safety invariants —
unsourced facts on screen, wrong citation page, invalid quote — were **zero in
every observed run**, enforced separately from model answer quality, which is
reported as a distribution across a frozen evaluation set.

- **369 unit · 77 database · 104 Playwright browser tests**, plus 37 mutation
  tests proving the evaluators can fail.
- Frozen evals: 30 Q&A cases + 21 red-team probes (last run 28/30, 13/18),
  23 comparison cases with 17/17 hard gates, 41 workflow cases with 19/19.
- Knowledge base frozen at 3 documents / 20 pages / 45 chunks, verified
  unchanged by every run.

## What it deliberately does not do

No final recommendation and no suitability determination — that is the product
boundary, not a missing feature. No client communication capability at all —
absent, not disabled. All products, carriers, and clients are fictional; every
PDF page is stamped as a demonstration document, and the gaps between demo and
production are enumerated in the repo, including the inconvenient ones.
